**Short answer:** [Batch PDF](/batch-pdf) applies the same operation to many PDFs, one after another, with no fixed file limit, and a file that fails is marked with the reason while the rest finish. It is a Practice tool.

One PDF is a task; two hundred is a chore. Compressing a month of scanned invoices, stripping metadata from a folder before publishing, or numbering a stack of exhibits one at a time wastes hours. Batch processing runs the same job across many files in one go. This guide explains how it works, how it behaves when something goes wrong and how to plan a big run.

## What batch is

[Batch PDF](/batch-pdf) takes many PDFs and applies the same operation to each, then hands back the results. It is a Practice tool. Like every tool here, each file is processed by your own browser and never leaves your device. The page is blocked from sending them anywhere.

## How to run a batch with LeafLock

1. Open [Batch PDF](/batch-pdf).
2. Add your files.
3. Choose the job to run on all of them.
4. Start the batch and watch the list as each file finishes.
5. Download the results.

## How many files?

There is no fixed limit. Files are processed one after another so your device does not run out of memory. A large batch therefore takes a while, but it gets through. Leave the tab open and your device awake until it finishes.

## What if one file fails?

The rest carry on. Any file that cannot be processed, for example because it needs a password, is marked in the list with the reason, and the others still finish. You can fix the problem file separately, such as with [Unlock PDF](/unlock-pdf), then run it again on its own.

## Does a batch use up my daily limit?

No. A whole batch counts as one job, however many files are in it. That is the main reason to use it for large sets, compared with running a single tool repeatedly.

## Planning a big run

1. **Test on two or three files first.** Check the output before committing to hundreds.
2. **Sort out the odd ones.** Password-protected, damaged or very large files are where batches stumble. Try [Repair PDF](/repair-pdf) for a damaged one.
3. **Name outputs clearly,** so you can tell originals from processed copies.
4. **Keep the originals.** Batch makes new files; delete the old ones only after checking.
5. **Check a sample of the results,** not just the first.

## Good jobs for a batch

- **Compress** a folder of scans before archiving or emailing: [Compress PDF](/compress-pdf).
- **Remove metadata** from every file before publishing a set: [Remove metadata](/remove-metadata).
- **Stamp numbers** across a production: [Bates numbering](/bates-numbering), which numbers across files in order.
- **Add a watermark** to every page of every file: [Add watermark](/add-watermark).
- **Convert** a folder of images or documents to PDF.

## Memory and device limits

Everything runs on your device, so very large PDFs or very large batches depend on how much memory it has. On a phone, use smaller batches. If a run stalls, split the folder in two and run each half.

## Combining outputs

If you need one file at the end, run the batch first, then join the results with [Merge PDF](/merge-pdf); see [how to merge PDFs without uploading them](/guides/merge-pdf-without-uploading).

## Summary

1. Batch applies one job to many files, entirely on your device.
2. Files run one after another; there is no fixed limit.
3. A failed file is flagged and the rest continue.
4. The whole batch counts as one job against your daily limit.
